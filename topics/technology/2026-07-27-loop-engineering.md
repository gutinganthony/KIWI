## 一句話

**下 prompt 是自己做工；寫 loop 是管理工人。** 差別在於「檢查產出、決定下一步」這件事由誰做——
現在是你在做，loop 的目的是把它交出去。

---

## 1. 原文重點

### 1.1 你現在的工作方式

你下 prompt → Claude 改檔 → 你跑測試 → 壞了 → 你貼錯誤回去 → 它再試。
二十分鐘後你發現：**你一直在保姆式盯著那件你本來想外包出去的事。**
你自己就是那個迴圈——每一輪都是你在檢查工作、決定下一步。

### 1.2 Loop 的五拍

再花俏的 loop 都只有這五步：

1. **找工作** — 開啟中的任務、失敗的測試、未讀信、資料夾裡的檔案
2. **做一件** — 一次一項，像你手工做那樣
3. **自我查核** — 第二輪確認「真的做完且正確」，不是「有產出」
4. **記錄** — 寫下已完成的，才不會重做或迷失位置
5. **再來一輪** — 重複到沒東西為止，然後停下或叫你

### 1.3 跟 cron 排程差在哪（關鍵）

cron 跑固定腳本：同樣步驟、每次一樣、沒有思考。
**loop 中間有一個決策者。** Claude 看當下狀況、挑下一個動作、執行、檢查結果，
然後決定：繼續／重試／撤回／停止。

> 那個中間的判斷就是全部的重點。腳本沒辦法看著一個壞掉的測試想出另一種修法，Claude 可以。
> 這件事是等到模型好到能在工作中途做真實判斷之後才成立的。

### 1.4 最有說服力的例子：假來源

叫 Claude 寫一頁 brief，它會給你乾淨自信的內容＋底下一串來源。**其中有些是編的。**
連結打不開，或打開了跟它宣稱的不一樣。單次 prompt 永遠抓不到這件事，
因為 **Claude 到有人真的去點那個連結為止，都覺得自己是對的。**

改成 loop，並加上一個**可量測的門檻**：

> 每個主張至少三個來源，且每個連結都必須打得開、內容真的支持該主張。

它就會寫完 brief 後逐條開連結，丟掉死連結與假連結，找替代來源，
一直檢查到頁面上每一個來源都打得開為止，然後停。
**它不會膩，也不會跳過無聊的那幾條。**

### 1.5 兩種指令

| 指令 | 型態 | 用在什麼時候 |
|---|---|---|
| `/goal` | 有終點線 | 「做到這件事為真為止」。每輪結束由另一個 Claude 檢查「到了嗎」，沒到就把原因餵回第一個。到了自己停。 |
| `/loop 30m ...` | 只有節奏 | 「每 30 分鐘看一次」。沒有終點線，只是盯著某個東西。 |

原文強調：**每輪之後那個自我檢查，就是「真 loop」與「跑一次然後祈禱的 prompt」之間的全部差別。**
多數強力的 loop 從 `/goal` 開始。

### 1.6 憲章模板（大型工作用）

一行的 goal 對小工作夠了；步驟多的工作要給 Claude 一份完整憲章：

```
GOAL              用一兩句描述完成狀態。要具體、要可量測。
WHERE THE WORK IS 告訴它去哪找工作（掃哪個資料夾／讀哪份 TODO／查哪個看板）。
HOW TO WORK       一次一項、做完才換下一項；沿用既有檔案的模式，不要自創；
                  需要「只有我能決定」的（花錢、刪東西、寄信給人）→ 停在該項、
                  丟進 "needs me" 清單、繼續下一項。
HOW TO CHECK      每完成一項，先證明它完成才能標完成。
YOURSELF          「查核＝證據，不是自信。」失敗就修了再查；同一項三次失敗
                  → 記為 blocked、往下走。
HOW TO REMEMBER   維護一個 LOOP-STATE.md：項目名、狀態（done / blocked / needs me）、
                  改了什麼、下一輪該知道什麼。每輪**先讀這個檔**，才不會重做。
WHEN TO STOP      全部完成或全部記為 blocked，或本輪已完成 N 項 → 停，並給簡短報告。
```

> **狀態檔是那個安靜的英雄。** 沒有它，每一輪都從零開始；有了它，loop 從上次停的地方精準接手，
> 即使它是排程跑的也一樣。

### 1.7 什麼時候「不要」做 loop（原文誠實的三點）

1. **一次性任務不需要 loop。** 單一答案的工作，普通 prompt 更快。loop 的設定成本要靠「重複發生」或「很多零件」才賺得回來。
2. **loop 更貴。** 會自我查核與重試的 loop，每一項要跑好幾次 Claude；在額度制方案上你會更快撞到上限。
3. **模糊的工作不屬於 loop。**「想一個更好的產品策略」不是 loop。先去把真正的目標弄清楚。

## 2. 對 KIWI 的意義（重點在這節）

### 2.1 我們已經做出這套的一半，缺的是第三拍

| 五拍元件 | KIWI 已有的東西 |
|---|---|
| 1 找工作 | 13 支 GitHub Actions workflow、`scripts/agenda_reminder.py` 每週六解析 AGENDA |
| 2 做一件 | 各 workflow 的 fetch/計算腳本 |
| **3 自我查核** | **← 空的。這是所有事故的來源。** |
| 4 記錄 | `AGENDA.md`、`projects/*/data/`、`docs/history.json` |
| 5 再來一輪 | cron schedule |

`topics/technology/mac-manual-homework.md` 其實就是原文講的 **"needs me" 清單**——
同一個發明，我們早就做出來了，只是沒意識到它是 loop 的一個標準零件。

### 2.2 第三拍缺席的代價（已經發生過）

`agents/LEARNINGS.md` 2026-07-26 條：07-22 週報有 **9 檔價格誤植**
（Koh Young 誤 +59%、Intekplus 誤 −54%、FORM +22%、Towa +18%、Mersen +12%…），
並憑錯值產出「Koh Young +20.2%🚩 反漲脫離累積區」「PLAB +16.6%🚩 近 $2B」等**假觸發判定**。

這就是 §1.4 的假來源問題換了個外衣：**沒有任何一步逼模型去驗證，它就會自信到底。**
教訓當時被寫進 LEARNINGS——但 **LEARNINGS 的規則要靠下一個 session 記得讀；
寫成 loop 驗收條件的規則是每一輪都被強制執行。** 這是本文對我們最大的價值。

### 2.3 我們的 13 支 workflow 全部是 cron，不是 loop

它們跑固定腳本，中間沒有決策者。所以它們會安靜地產出錯的東西而不自知
（除了硬失敗會有 Telegram 推播）。**升級路徑不是加更多 cron，是在既有 cron 的產出上加一層會判斷的驗收。**

### 2.4 三個該建的 loop（依報酬率）

1. **週報重定價驗收 loop**（`/goal` 型）→ 憲章已落地：`agents/loops/weekly-repricing-audit.md`
   把 LEARNINGS 那條教訓變成機器每輪都會跑的驗收條件。
2. **Mac 功課清帳 loop**（`/goal` 型）→ 憲章已落地：`agents/loops/mac-homework-clearing.md`
   清單積欠 20+ 項、最老 3 週；月度自檢第 6 題自己說 >14 天＝執行力警訊。
3. **裁判日 loop**（`/loop` 型，尚未建）
   AGENDA 上一堆硬日期裁判點（7/30 記憶體重跑、8/7 JEM Q1、8/10 群翊營收、8/13 Seikoh Q1）。
   現在 `agenda-reminder.yml` 只**提醒**你；loop 版本可以先把數字抓回來、按事前寫好的
   「結果 X → 動作 Y」預案跑完判定，你只收結論。

### 2.5 三個「不要」對我們的特別意義

- **「模糊的工作不能塞進 loop」** 對 KIWI 有加倍的重要性：月度自檢第 7 題
  「深掘檔數 ÷ 實際執行動作數 >5:1＝研究代償發作」。
  **loop 會讓研究產能暴增；若不先把「執行動作」定成 loop 的終點，只會更快產出更多沒人執行的研究。**
  → 鐵律：**KIWI 的任何 loop，GOAL 那格必須寫成「某個檔案／某個決策被更新」，不是「產出一份分析」。**
- **額度**：LEARNINGS 2026-07-26 記錄 WebSearch 有 session 級 200 次上限、曾用罄卡死收尾。
  自我查核型 loop 每項多輪 → **憲章必須寫死搜尋預算**（每項最多 N 次、先列必查清單再搜）。
- **判斷題不要 loop**：出場手冊那種「要 Jake 自己決定減倉條件」的工作不是 loop。
  但**手冊寫完之後**，「條件是否已觸發」就是完美的 `/loop` 標的。

## 3. 環境事實校正（不要照原文照抄）

- **`/loop` 在本環境可用**（skill 清單有列，並有搭配的排程工具）。
- **`/goal` 未在本 session 的可用 skill 清單中出現**——原文說「看不到就更新 Claude Code」，
  雲端 session 無法驗證，需在 Mac 本機確認。
- **但 `/goal` 的價值不在指令，在憲章。** `agents/loops/` 下的兩份憲章即使用普通 prompt 貼進去也能跑，
  差別只是要人工起頭、不會自動續跑。
