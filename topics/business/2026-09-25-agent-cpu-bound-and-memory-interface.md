## 0. 一句話

> **AI Agent 會「執行」，而執行必須在 CPU 上發生；Agent 迴圈是串行的，所以延遲無法被平行化掩蓋。**
> **⇒ CPU 從 AI 系統的週邊角色，變成決定系統整體效率的關鍵瓶頸。**

# 一、原文邏輯（一手）

## 1.1 三則新聞，主角全是 CPU

2026 上半年三個月內：
- **2 月** — NVIDIA 宣布 **Meta 將在正式環境大規模部署 Grace CPU** 伺服器，下一代 **Vera** 接著導入
- **3 月** — **Arm 發表成立 35 年來第一顆自家晶片 AGI CPU**，正式跨入實體晶片市場（**與自家客戶正面競爭**）
- **4 月** — AWS 自研 **Graviton** 獲雲端大廠採用，**Meta 將以數千萬顆 Graviton 核心**執行 Agentic AI 背後的 CPU 密集工作

**供應商角色同時在變**：以 GPU 聞名的 NVIDIA 開始**單獨販售 CPU**；以 IP 授權為本業的 Arm 開始**自己做晶片**；雲端業者的自研 CPU **成了外部大廠的採購對象**。

## 1.2 🔴 機制：Agent 會「執行」，而執行是串行的

| | Chatbot | **AI Agent** |
|---|---|---|
| 運作 | 一個 Prompt → 一次推論 → 輸出 | **觀察 → 推理 → 行動**，一個任務可能串接**數十次**迴圈 |
| CPU 角色 | 只做前後處理、餵資料進 GPU | **跑程式碼、瀏覽網頁、用工具**，並提供**作業系統／檔案系統／網路／沙箱**這個「環境」 |
| 可平行化？ | — | ❌ **串行**：後一步的輸入來自前一步的輸出，**無法靠平行化掩蓋或繞過** |

**兩個直接後果：**
1. 🔴 **運算成本被放大** — 論文實測：**CPU 端處理時間可佔 agent 工作負載總延遲的 50%–90%**（`arXiv:2511.00739`, 2026/4）。多輪延遲累積 ⇒ **GPU 等昂貴元件空轉**
2. **電力預算被稀釋** — 固定功耗下，**CPU 每多耗一瓦，GPU 就少一瓦**

## 1.3 四大設計趨勢

| 趨勢 | 內容 | 關鍵句 |
|---|---|---|
| **1. 追求更高 IPC** | 設計重心從雲端時代的「**每核成本**」轉向「**單核效能**」。需要：預測執行路徑、在等待中繼續推進、大快取就近備妥資料 | **效能指標從「峰值」走向「滿載」**；**使用者體驗被最慢的核心決定** |
| **2. 記憶體頻寬大幅提升** | Agent 各自帶上下文與執行狀態；**存取零散難預測、快取命中率遠低於傳統負載**。解法：**SOCAMM**（LPDDR5X，記憶體做得更靠近處理器、大幅降低每單位頻寬功耗）、**MRDIMM**（專屬晶片合併兩列資料，同時脈雙倍傳輸） | — |
| **3. 更緊密的晶片內部 fabric** | 延遲要**低**且**可預期**——不能有「快的位置」與「慢的位置」。核心數增加＋光罩面積上限＋SRAM 難微縮 ⇒ **Chiplet 成主流**，但跨 chiplet 引入額外功耗與延遲 | NVIDIA Vera ＝ **6 顆 chiplet**（1 運算＋4 記憶體＋1 I/O），核心與快取留在運算 chiplet 內由 **SCF** 緊密連接 |
| **4. I/O 頻寬必須跟上記憶體頻寬** | 路徑：DRAM →（記憶體頻寬）→ 晶片內部 →（fabric 頻寬）→ PCIe／專用連結 →（I/O 頻寬）→ GPU/網卡/儲存 | **吞吐量被較窄的一端決定**；I/O 跟不上，**I/O 就取代記憶體成為新瓶頸** |

## 1.4 三種廠商架構 —— 差異在 **Fabric 與封裝**

| 廠商 | 設計 | 追求 | 代價 |
|---|---|---|---|
| **NVIDIA Vera** | 運算與快取高度整合在**同一 monolithic die** | 最高頻寬、**最低且一致的延遲**（應對編排與 Host 角色） | **受光罩面積限制，核心數較低** |
| **Arm AGI CPU** | 各自功能完整的**多 chiplet 封裝** | 核心**獨立性與密度**（應對多沙箱 fan out） | 跨 chiplet 的功耗、頻寬、延遲 |
| **Intel Diamond Rapids** | **運算與快取分離＋垂直堆疊** — 運算 die 用最先進製程，**快取用成熟製程** | 快取又大又便宜；3D 堆疊減少橫向繞路 ⇒ 提高 IPC | **3D 封裝的製造複雜度、良率風險、散熱挑戰** |

> 🔴 **原文最深的一句**：Agent CPU 承擔**兩種性質相反的工作**——
> **Host 與編排（追求低延遲，要把資源集中）** vs **沙箱執行（追求高密度平行，要把資源分得更細）**。
> **兩者本質上無法兼顧，所以不會有一種設計同時滿足。Fabric 與封裝的差異，就是各家的資源分配哲學。**

## 1.5 結論與兩條觀察線

1. **封裝會是主要的硬體差異化來源** — 邏輯製程推進放緩、核心微架構高度收斂的情況下，
   **封裝決定了：每個功能區塊用什麼製程（成本）、資料走多遠（延遲）、電怎麼送進去（能效）、總共能用多少面積（核心數）**
2. 🔴 **軟體需要為 AI agent 重新設計** — 傳統軟體為人類使用者設計，有許多 Agent 不需要的介面與延遲。
   **軟體迭代以月計，晶片開發動輒數年 ⇒ 「在硬體設計收斂之前，軟體很可能是短期內更大的槓桿。」**
